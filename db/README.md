# DB 테이블 적용 방법

현재 저장소에는 PostgreSQL 서버 자체가 포함되어 있지 않습니다. 테이블 정의는
Spring Boot가 자동으로 읽을 수 있는 아래 Flyway 마이그레이션 파일로 만들어져 있습니다.

`backend/src/main/resources/db/migration/V1__create_ai_tables.sql`

초기 데이터는 별도의 Flyway 마이그레이션으로 저장되어 있습니다.

`backend/src/main/resources/db/migration/V2__seed_ai_tables.sql`

docker에 의존성 연결 해놨으니 docker compose up --build 하시길

'
- Host: localhost
- Port: 55432
- Database: spovisor
- Username: spovisor
- Password: spovisor
- 
'

1. 애플리케이션이 시작되면 Flyway가 `V1__create_ai_tables.sql`을 실행하고,
연결한 `spovisor` 데이터베이스 안에 다음 4개 테이블이 생성.

- `spot_cache`
- `spot_relation`
- `spot_congestion`
- `user_survey`

2. 이후 Flyway가 `V2__seed_ai_tables.sql`을 실행하여 다음 데이터를 삽입.

- `spots.json` 전체 3,255건 → `spot_cache`
- `relations.json` 전체 3,254건 → `spot_relation`

`V2` 파일도 Git에 함께 커밋해야 다른 팀원이 저장소를 내려받고 애플리케이션을
처음 실행할 때 동일한 초기 데이터가 자동으로 생성됨. 즉, Flyway는 이미 실행한
버전을 다시 실행하지 않으므로, 나중에 데이터가 변경되면 `V3__...sql`처럼 새
버전의 INSERT/UPDATE 마이그레이션을 추가해야 함 (중요!!! V4, V5 이런식으로 업데이트 버전을 추가하는 형식)

## psql에서 직접 실행

이미 `spovisor` 데이터베이스와 PostgreSQL 사용자가 있다면 다음처럼 직접 실행할 수 있습니다.

```bash
psql -h localhost -U spovisor -d spovisor -f backend/src/main/resources/db/migration/V1__create_ai_tables.sql
```

즉, SQL 파일을 저장한 것만으로 DB 서버에 테이블이 생성되는 것은 아니며, 위의 Flyway 실행 또는 `psql` 명령을 수행해야 실제 DB에 반영됩니다.

초기 데이터를 psql로 직접 넣으려면 테이블 생성 후 아래 명령을 실행.

```bash
psql -h localhost -U spovisor -d spovisor -f backend/src/main/resources/db/migration/V2__seed_ai_tables.sql
```

## PostgreSQL 타입 대응

캡처의 컬럼명·길이·NULL 여부를 유지하면서 PostgreSQL에서 실행되도록 다음 두 타입만 대응

- `DATETIME` → `TIMESTAMP`
- `AUTO_INCREMENT` → `GENERATED BY DEFAULT AS IDENTITY`

`vector`와 `keywords`, `last_survey`는 `JSON`으로 생성. JSON 내부 검색이 많아지면 추후 `JSONB`로 변경하고 GIN 인덱스를 추가할 수 있음.
